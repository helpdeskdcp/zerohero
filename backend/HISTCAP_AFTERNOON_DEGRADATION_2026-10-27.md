## Root cause (chain)
1. **Trigger (when):** a pre-open AB9019 on the greeks probe disables greeks for 6 h (silently) -> greeks flip on ~13:00-14:00 IST (or at a restart).
2. **Amplifier (why it hurts):** the moment greeks flow, every capture cycle is followed by an inline greeks_engine CYCLE pass that is O(all history): full scans + sorts over a 3.2 M-row table per expiry, 100-1500 s each, run synchronously in the capture thread of the single uvicorn process on a 2-vCPU box. Capture cadence collapses (cycle = capture + engine), the machine saturates (CPU/IO), the same non-sargable `julianday()` queries in the 5-minute scans stretch to 15-28 min and overlap, writers hit `database is locked`.
3. **Not the cause:** the Angel feed (greeks calls themselves are ~10 per cycle, 15 s cache), the 3 s execution-delay change (restart only moved the onset earlier on 26-Oct), the arena priority capture (separate, short writes).
4. Same thing is going to happen **today**: the 07:10 restart caused NIFTY and SENSEX to be marked UNAVAILABLE (retry_after 1793086811 = 13:10 IST), so the cascade should start ~13:10 IST.

## Proposed fixes (none applied; ordered by value/risk)
1. **Stop the amplifier (highest value, low risk):** call `greeks_engine().run_once("NIFTY", expiries=[current opt_expiry], session_date_ist=today, mode="CYCLE")` (or skip when the last run is < N min old) instead of all history; move it out of the capture thread (separate worker/interval, with its own statement timeout). Expected: pass drops from minutes to seconds; cadence returns to ~45 s.
2. **Make the queries sargable:** replace `julianday(received_ts)` comparisons/ORDER BY with direct string comparison on the stored ISO-Z format (same lexicographic order) so `ix_greeks_lookup`/`ix_quotes_*` are used; same for `angelone_chain._ro` temp views (260 s -> ~2 s; my own reader already does this). Add regression tests with a timing/EXPLAIN assertion.
3. **Fix the trigger:** do not cache `UNAVAILABLE` for 6 h on AB9019 when the segment is closed/pre-open (use a short TTL, e.g. 300 s, or only cache after a probe during an OPEN session); log a skipped-greeks counter in `capture_runs` so a silent skip is visible.
4. **Observability:** per-stage timings (quotes / greeks / engine / candles / dhan) in `capture_runs`, and an alert when POLL cycle > 120 s.
5. Cron: `timeout`/`nice` on the 5-minute scans as a stop-gap (needs your approval; earlier proposal).
Immediate mitigation for today without code: none that is clean; avoid a restart in the afternoon; expect degradation from ~13:10 IST. If you want it prevented today, fix #1 (small, testable) is the one to ship before 13:00 with a restart now (market is closed until 09:00 MCX; no active trades).
