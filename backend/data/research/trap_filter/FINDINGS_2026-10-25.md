## The first run was wrong (leakage) — kept for the record
The first run (results_LEAKY_first_run.json) printed GO-SHADOW (AUC 0.65, 8/8 years, +0.20 R). It was an implementation bug, not an edge: the feature prior_fail ("earlier failed breakouts same session/side") counted a trade's OWN stop-out whenever the stop was hit on its entry bar (exit_ts == entry_ts), so every instant loser carried prior_fail = 1 = label leak. Found because dropping that single feature collapsed AUC 0.645 -> 0.53 and the table showed prior_fail=1 win rate 13 %. Fixed (strictly earlier trades only), regression test added, whole study re-run once; the spec was not changed.

## What this means for "trap / SL-hunt detection"
Price-only proxies for traps (adverse wick, sweep-and-close-back, distance to previous-day high/low = stop-cluster proxy, prior failed breakouts, VWAP/day-range position, time of day, gap, momentum into the zone) do not separate winners from losers on 4,357 trades across 6 indices and 8 test years. Where a stop hunt would actually be visible is order flow / book depth (aggressor volume, absorption, depth pull) - that data exists for only the last 7-21 days here, so a trap detector built on it cannot be validated yet. Forward collection (dense L2 capture + the live zone-breakout paper trades, each stored with these features) is the only route; revisit at ~300 live signals.
