# Hybrid Market Profile v13.0 — Pine code audit (2026-10-14)

Classification: **BUG** (wrong versus the script's own evident intent or a documented rule), **FLAW** (works as written, harmful for the stated use), **DESIGN** (deliberate choice, noted), **LIMITATION** (cannot be settled with the evidence available). "Corrected" means a backward-compatible option exists in the port; the reference behaviour is never changed silently (`Params()` defaults reproduce Pine).

| # | item | class | finding and evidence | recommended correction / port handling |
|---|---|---|---|---|
| 1 | Prior-day close / opening gap | **BUG (conditional)** | `priorDayClose := close[1]` is the previous *chart bar*. Correct on a contiguous regular-session chart; wrong when extended-hours bars exist or the prior session's last candle is missing. On NIFTY data that includes out-of-session bars the Pine formula is 0.114 pct-pt away from the official daily-bar gap on average vs 0.077 for the session-aware version (worst: 2021-09-27 Pine −6.75% vs daily +0.44%). The remaining 0.077 is the exchange's official closing value ≠ last-minute close (same for both). | `gap.opening_gap_session_aware` (prior in-session close of the previous trading date, flags incomplete prior sessions); Pine version kept for parity. Tests: contiguous, extended bars, missing last candles, weekend/holiday, first day, MCX rollover. |
| 2 | MTF repaint / look-ahead / timeframe compatibility | **DESIGN + LIMITATION** | `f()[1]` with `lookahead_on` is the standard non-repainting idiom; truncated-data tests prove no future higher-TF bar is used. The comment "uses the last confirmed candle" is only true when the chart timeframe ≤ the requested one. With a requested TF **lower** than the chart TF (e.g. 3m on a 5m chart — the script's own default `tf1=3`) TradingView returns a different series; the port uses the last completed lower-TF bar **before** the chart bar opens (conservative, lagging) and flags it as `mtf_incompatible_tfs`. | Use chart TF ≤ 3m for MTF parity, or set `tf1` ≥ chart TF. **UNVERIFIED against TradingView.** |
| 3 | Pivot confirmation delay | **DESIGN** | A pivot is known `pivotLen` bars late (25 min on 5m with 5). A break of a level before its pivot is confirmed produces no BoS. Tie rule: TradingView keeps the newest of equal extremes (left ties allowed, right ties not); an earlier port version differed (fixed, D2). | `pivots_tv`; tests. |
| 4 | Session timezone, MCX hours, holidays | **LIMITATION** | NSE/BSE fixed IST (no DST). MCX uses one session string for every commodity; real MCX hours differ by product and shift with US DST (not modelled). Exchange holidays are not modelled (a closed day simply has no bars). 3,663 NIFTY bars fall on Saturdays/Sundays (budget/Muhurat sessions) and are excluded by `…:23456`. | Instrument-specific session through `Params.session`; see `profile.session_for`. |
| 5 | Missing volume → VWAP | **FLAW** | With `useVWAP=true` and no volume, `ta.vwap` is `na` and the filter **passes silently**: on index data (volume 0) the filter is a no-op although the user believes it is active. | `vwap_missing_blocks=True` blocks instead (default False for parity); `vwap_proxy` (TWAP) exists only in the fixed variant and is labelled. Test. |
| 6 | Continuation while a setup is pending | **DESIGN** | Continuation is independent of pending. Consequences verified by fixtures: RETEST takes precedence in the label when both are true; a pending SELL blocks creation of a new BUY setup, but a BUY continuation still fires and consumes it; any signal clears the pending one. | Documented; fixtures + literal-reference parity. |
| 7 | Pending expiry boundary | **DESIGN** | Expired when `bar_index − pendingBar > retestBars`: a retest on bar `pendingBar+retestBars` is valid, one bar later is not (expiry is processed before the retest test). | Fixture. |
| 8 | Same-bar SL and target | **DESIGN** | SL first. Measured: crediting T4 instead changes mean R by +0.0013 at 1-minute bars (ambiguity is rare for 4R targets); it would matter for 1R targets (not measured). | `favorable_first` sensitivity switch only. |
| 9 | Trade open across session end / overnight | **FLAW** | No end-of-day exit: 30% of 5m trades are carried overnight and one 1m trade stayed open 232 days (gap candle with R = 520 bps). Gap-through-stop is booked at the stop level (−1R) in the as-plotted accounting, which inflates gross (+0.15 R at 5m collapses to ≈0 with an EOD exit). | `eod_flat`, `gap_fills`; `fixed_params`. |
| 10 | State reset / historical recalculation | **LIMITATION** | Pine `var` state is rebuilt from the first loaded bar, so the right-edge state depends on how much history TradingView loaded — most visible with trades that can stay open for days (#9). Port check: final-bar state recomputed from only the last 3, 8 or 20 sessions equals the full-history state in 50/50 random end bars (`fixed_params`, with EOD exit). Not tested for the as-plotted (no-EOD) mode. | The dashboard's 8-session window is consistent for the fixed variant. |
| 11 | Quantity formula vs actual risk | **FLAW (for options)** | `qty = capital·risk/max(R·pointvalue, mintick)` is an index-point quantity, fractional, with no lot size, premium, delta, costs or margin. With ₹12,000 / 1%: ₹120 budget; one NIFTY lot (75) risks ≈ ₹1,144 on a 30-point index stop. | `option_model.plan_option_trade` (premium stop from delta/gamma, lot/tick rounding, charges, capital). |
| 12 | Duplicate alerts / de-duplication | **FLAW** | `alertcondition(buySignal …)` also fires when `candidateR < mintick` and no trade exists. No de-duplication exists across recalculations. | `alerts.py`: deterministic ids `sha1(symbol|tf|bar_open|name|direction)`, `AlertDeduper` (replay and overlapping windows emit once), `no_trade` flag. |
| 13 | Dashboard target status after a trade closes | **DESIGN (no bug)** | `f_targetText` returns "—" when not active, `nextTarget` is shown only when active; `lastResult` reads "STOPPED" even if T1–T3 were reached (the milestones are lost in the text). `done1..4` stay true until the next entry. | State dict exposes `max_target` per trade. |
| 14 | Profile-detection false positives | **BUG** | Substring tests: RELIANCE, SPICEJET, PERSISTENT → "Indian Index/Options" (contain CE/PE); GOLDBEES, SILVERBEES → MCX. `profileKnown` only changes the dashboard text; **signals are not gated by it** (the dashboard can say "PROFILE NOT RECOGNIZED" while signals still fire). | `profile.detect_profile_corrected` (exchange + instrument type first, option-ticker regex); Pine rules kept in `detect_profile_pine`. 13 parameterised tests. **TradingView symbol metadata was not available** — the corrected detector needs the real `syminfo.type/prefix` to be validated. |
| 15 | Comment vs calculation | **minor** | Alert text "Confirmed BoS/CHoCH reversal" fires on CHoCH only (never BoS); "Planned Qty*" has no footnote; `bearStar` requires a bearish close (a classical shooting star may be either colour); `showStructureEvery` thins labels only. | Documented. |
Additional (from the earlier review, unchanged): unbounded stop distance (p99 67 bps, max 757 bps) · entry at the signal close is not executable · no partial/break-even logic (a trade that touched T3 then stopped is "STOPPED").
